# latex-academic-translate

> LaTeX → Chinese, with formulas still rendering.
>
> 让英文 LaTeX 论文片段在 AI 对话里译得准、读得顺、原意不丢。

latex-academic-translate 是一个纯提示词 Skill：把含 LaTeX 的英文论文片段译为规范中文，并让结果在当前对话里**尽可能可读、可渲染**。它不维护逐结构规则清单，只给出一个目标、几条边界和一条包裹规则，其余交给调用方的 AI 按自身渲染能力自主优化；只有公式单独包裹，正文不残留裸命令，数学含义不变、遇到无法解析的写法可自行展开或降级，不丢原意、不新增解释。运行时只需一个 `SKILL.md`，无脚本、无依赖、无网络上传。

## 它解决什么问题

| 常见痛点 | 一般做法的结果 | 本 Skill |
|---|---|---|
| 裸 `equation` 环境贴进对话 | 打印成一行反斜杠源码，公式不可读 | 换成 `$$...$$`，每个公式独立包裹 |
| 把「保真」理解成「保留所有 LaTeX 字节」 | 一堆读不出来的排版命令、路径参数堆在译文里 | 只保留承载原意的信息，纯排版字节可删 |
| 正文里残留 `\cite`、`\label` 等裸命令 | 渲染层遇到未定义控制序列，把命令标红 | 转成可读文字或并入公式，正文不留反斜杠命令 |
| 论文自定义宏在对话里没有导言区 | 公式内符号被标红或整块解析失败 | 由 AI 自行展开、替换或降级，数学含义不变 |
| 用代码块或引用块框住文字、伪代码、图片说明 | 整篇译文被容器割裂，阅读不连贯 | 只有公式需要包裹，其余自然成文 |
| 为每种结构写一条规则 | 规则越堆越多，遇到新写法仍失效 | 目标驱动 + 自主权，没见过的写法也能自行优化 |

## 不是什么

- 不是 LaTeX 编译器，不生成 PDF。
- 不是 `.tex` 文件生成器：运行时不写任何文件，结果只在对话里返回。
- 不是通用翻译器；不含 LaTeX 的纯文本请直接用普通翻译。
- 不是英文润色工具，也不解释 LaTeX 命令含义。
- 不是英译工具，当前只做英→中。
- **不是可视化渲染组件**：公式、伪代码、图片最终能不能显示，取决于调用方 AI 的前端；本 Skill 只支配「译文怎么组织、怎么包裹、哪些内容转成可读文字」，不承诺视觉效果。
- **不是规则清单或白名单**：不为每种 LaTeX 结构预设处置方式。

> **为什么不做英译**：把中文补译为英文需要「已有英文只读、只改中文片段」的另一套约束，会让规则量近乎翻倍，故不在本 Skill 范围内。需要中→英请走通用学术翻译流程。

## 核心设计

1. **一个目标**：尽可能可读、可渲染，不影响阅读、不改变原意；实在无法渲染又不承载语义的部分可以删。可读与「保留原文写法」冲突时，以前者为准。
2. **一条包裹规则**：只有公式用 `$...$` / `$$...$$` 且每个公式单独包裹；编号、标签、引用置于公式之外；文字、代码步骤、图表说明一律不加容器。
3. **正文不残留裸命令**：以反斜杠开头的命令不出现在译文正文里，其信息要么并入公式、要么转成可读文字、要么删去（不损原意）。
4. **数学含义不变，形态可自主**：公式源码默认不动；遇到渲染层无法解析的写法（例如自定义速记宏），由 AI 自行展开、等价替换、补最小定义或降级为可读文字。
5. **把判断权交给 AI**：渲染层能力因宿主而异，Skill 不列举结构类型、不设逐结构规则；同一输入在不同宿主下呈现不同是设计结果而非缺陷。
6. **收尾说明**：全部译文结束后输出一条横线，横线后用一句话说明本次对 LaTeX 做了哪些修正；不列点、不展开、不解释原因。

完整规则见 [`SKILL.md`](SKILL.md)；[`references/examples.md`](references/examples.md) 只是某一种呈现效果的展示，**不是规则**。

## 安装

把本目录放到用户级技能目录，重载会话后生效：

```
~/.workbuddy/skills/latex-academic-translate/
├── SKILL.md          # 唯一必需文件
├── README.md         # 可选
└── references/       # 可选，仅示例
```

`SKILL.md` 是运行时的唯一必需文件。触发依赖宿主读取 YAML frontmatter 中的 `description` 字段（WorkBuddy / Claude Code 一类 Skill 机制）。`references/` 里只有一个示例文件，即使宿主完全不加载也不影响规则完整性。

**建议把发布仓库与安装目录分开**：安装时只需复制 `SKILL.md`、`README.md` 与可选的 `references/`。

## 用法

带标签最稳，标签本身不会出现在译文里。以下示例为自造文本，不含任何真实论文内容。

```
中译：
\subsection{Setup}
We evaluate on three benchmarks with $\lambda > 0$ and $\|\vx\|_1$.
\begin{algorithmic}[1]
\FOR{$k=1$ \TO $K$}
  \STATE $\vx_{k+1} \leftarrow \vx_k - \eta \nabla f(\vx_k)$
\ENDFOR
\end{algorithmic}
\begin{figure}[t]
\centering
\includegraphics[width=0.85\linewidth]{figs/convergence.pdf}
\caption{Convergence over 20 runs.}
\end{figure}
```

某个支持 Markdown 与 KaTeX 的宿主里，可能呈现为：

> ### 实验设置
>
> 我们在三个基准上评估，其中 $\lambda > 0$ 且使用 $\|\vx\|_1$。
>
> 算法步骤：
>
> 1. 对 $k=1$ 到 $K$，令 $\vx_{k+1} \leftarrow \vx_k - \eta \nabla f(\vx_k)$。
>
> 图 convergence.pdf：20 次运行的收敛曲线。
>
> ---
>
> 已把公式单独包裹、伪代码改写成可读步骤、图片模块压缩为文字说明，并删去无渲染意义的排版字节。

五个要点：公式逐个单独包裹；正文没有残留裸命令；伪代码改写成可读的中文编号步骤且不被代码块框住；无渲染意义的图片排版参数被压缩成一句说明，文件名与图题原意都保留；译文末尾以横线分隔，附一句极简的 LaTeX 修正说明。若公式里有渲染层不认识的自定义宏，AI 会自行展开或降级，而不是把命令标红。**这只是其中一种可能结果** —— 渲染层不同，呈现可以不同。

不加标签也可用：含 LaTeX 特征的文本默认按中译处理。可用标签：`中译` / `译中` / `/zh` / `ZH`。

## 已知限制

- **渲染效果由调用方 AI 的前端组件决定**，本 Skill 无法影响，也不承诺公式、伪代码或图片一定显示为可视化内容；它只支配译文的组织与包裹方式。
- 未定义控制序列可能被前端标红。Skill 的应对是避免把解析不了的字节写进译文，而不是修改前端行为。
- 同一输入在不同宿主、不同模型下呈现可能不同，这是自主权的设计结果。
- 公式在「数学含义不变」的前提下可能被展开、替换或降级为文字，因此不再保证与原文源码逐字节一致。
- 不解析参考文献库，不做宏包依赖推断，不生成 `.tex` 或 PDF。
- 不支持中→英，见上文范围说明。

## 目标用户与场景

适合用 AI 读译英文论文的硕博与研究者、把 LaTeX 片段贴进对话做笔记或组会汇报的人、不宜上传原文而需要本地翻译规则的用户，以及把「目标驱动而非规则清单驱动」当参考实现的 Prompt / Skill 工程实践者。

典型场景：读 arXiv 或会议论文时译摘要、定理与实验段落且公式仍可读；英文论文片段转中文读书笔记、组会汇报、课程讲义；把伪代码、图表模块转成连贯的中文叙述；断网或涉密环境下不上传原文的翻译规则。
